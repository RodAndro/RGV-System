1. Executive Summary & System Architecture

RGV-System is an enterprise-grade, multi-platform business operations management system engineered specifically for RGV Multi-Tech Services. The system unifies four core business operations—Customer Service Bookings, Physical Inventory & Asset Management, Field Equipment Borrowing & Returns, and Business Analytics & Compliance—into a synchronized ecosystem powered by a single source of truth database.

The Core Operational Vision: Customers submit and track technical service requests publicly without account friction; field employees manage assigned dispatches, review inventory, scan physical equipment via native Android QR scanning, and process returns on-site; administrators retain end-to-end command over approvals, stock thresholds, role-based security, automated backups, AI-driven demand forecasts, and tamper-evident audit trails.

1.1 Multi-Surface Ecosystem Architecture

Unlike disjointed solutions that rely on batch synchronization workers or independent data stores, the RGV System connects all client surfaces directly to a unified PostgreSQL engine (hosted on Supabase) sharing identical business constraints, relations, and transactional integrity.

2. Role-Based Access & Public Customer Portal

The system implements a strictly segregated role hierarchy. Public users interact without authentication to eliminate customer friction, while internal staff and administrators are protected by Spatie Role-Based Access Control (RBAC), multi-factor authentication (MFA), and session monitors.

2.1 Stakeholder Matrix & Operational Privileges

Role Client Platform Accessible Features Security Controls
Public Web Browser (Desktop & Mobile) Submit service booking requests, track booking progress in real-time, scan public inventory QR verification tokens, browse services. Zero credentials required; public rate throttling (30 req/min); CSRF protection; input sanitization.
Employee Web Portal + Flutter Android App Manage assigned service jobs, create equipment borrow requisitions, conduct stock checks, process returns, view notifications. Password hashing (Bcrypt); Mandatory MFA (TOTP / Email); Sanctum bearer token; Supabase AAL2 JWT; session timeout.
Administrator Admin Web Control Center Full oversight: approve/reject bookings, assign staff, manage inventory, execute backups, audit logs, AI forecasting, site settings. Admin middleware; MFA protection; Force-logout capability; Impersonation audit tracking; Password-confirmed deletion.

2.2 Public Booking Submission Engine

Customers can request service visits through an intuitive, mobile-responsive booking form accessible directly from the homepage (/booking). The interface is tailored to capture complete technical and scheduling specifications upfront.

Customer Information Captured
  • Full Customer Name: Contact person for service delivery.
  • Valid Email Address: Destination for instant lifecycle email alerts.
  • Contact Telephone: Direct phone number for technician field coordination.
  • Physical Service Address: Precise destination for on-site execution.
Service & Scheduling Parameters
  • Preferred Execution Date: Requested service calendar date.
  • Preferred Time Window: Morning / afternoon time slot selection.
  • Purpose Category: Installation, Maintenance, Repair, or Inspection.
  • Reason & Technical Notes: Detailed problem or work description.
Automated Reference Token Generation: Upon successful submission, the system issues a unique, tamper-resistant reference identifier formatted as BK-XXXXXXXXXXXXX (e.g., BK-20261025-A8F9). This reference code serves as the customer's permanent lookup key.

2.3 Public Real-Time Service Tracking Engine

Customers can monitor their service request at any time by visiting /booking/track/{reference} or entering their reference code on the homepage tracking form. The tracker reveals live operational milestones:

1. Pending ReviewAwaiting Admin

Request logged in database. Awaiting administrative review for technician availability and feasibility.

2. Approved & AssignedTechnician Set

Admin confirmed schedule. Designated technician is assigned and preparing required tools.

3. CompletedService Finalized

Technician executed work on-site, filed job remarks, and marked booking successfully fulfilled.

2.4 Public QR Code Asset Verification

Physical equipment managed by RGV Multi-Tech Services features durable QR tags linking to immutable public tokens (/inventory/qr/{token}). When scanned by clients or site inspectors:

  • Displays verified asset name, equipment category, unit specifications, and technical description.
  • Confirms official ownership by RGV Multi-Tech Services to prevent counterfeit equipment usage.
  • Safeguards sensitive internal details: Unit purchase costs, internal warehouse aisle numbers, and stock quantity counts remain strictly hidden from unauthenticated viewers.

3. Employee Operations: Web Portal & Flutter Android App

Employees represent the operational workforce of RGV Multi-Tech Services. They are equipped with dual interconnected interfaces: a comprehensive Web Portal for desktop dispatch management and reporting, and a high-performance Flutter Android App engineered for fast, hands-on field operations.

3.1 Employee Web Portal Capabilities

• Technician Command Dashboard

Centralized home screen displaying active assigned service bookings, pending equipment requisitions, items currently borrowed, overdue return alerts, and an unread notification counter.

• Assigned Dispatch Management

Technicians view complete customer details, service locations, and scheduling requirements. They can append job remarks, document field progress, and mark bookings as Completed upon job fulfillment.

• Equipment Requisition (Borrow System)

Searchable inventory catalog with real-time stock availability. Technicians submit multi-item borrow requests specifying required quantities, operational purpose, borrow start date, and expected return due date.

• Return & Condition Reporting

Itemized return workflow allowing staff to declare returned item condition (Good, Fair, Poor), document damage notes, specify warehouse return locations, and soft-delete closed records.

3.2 Flutter Android Mobile Application (Field Technician App)

The native Android app in mobile/ is purpose-built for agility in workshops, vehicles, and client job sites. It communicates directly with Supabase Auth and restricted PostgreSQL RPCs, guaranteeing operational independence even during web server restarts.

Mobile Feature Implementation Mechanism Field Technician Benefit
Hardware QR Scanner Integrated mobile_scanner with hardware camera acceleration. Point-and-shoot barcode/QR recognition on physical tool labels; zero typing required.
Manual Item Lookup Alphanumeric code search with real-time substring filtering. Instant fallback for scratched, dirty, or damaged QR tags, or low-light field conditions.
Direct Supabase RPCs Transactional stored procedures: borrow_request, return_items. App continues functioning even if the Laravel web application is restarting or offline.
Stock Reservation Automated atomic decrement of available quantity upon request. Prevents multiple technicians from reserving the same critical tools simultaneously.
Idempotent Returns Client-side UUID generation via Dart uuid package. Guarantees that poor network connectivity or double-tapping never creates duplicate return logs.
Mobile Security & MFA Supabase Auth with mandatory TOTP MFA (AAL2 compliance). High security; credentials encrypted using flutter_secure_storage.
Dual Mobile API Architecture: While the primary Flutter app uses direct Supabase PostgreSQL RPCs for maximum availability, the Laravel backend maintains a complete set of authenticated REST endpoints under /api/v1/mobile/* (protected by Laravel Sanctum bearer tokens with dedicated rate limiting of 20 req/min for auth and 120 req/min for operational endpoints) to support external integrations and legacy clients.

4.3 Complete Inventory & Asset Management

The inventory engine tracks tools, technical equipment, consumables, and replacement parts:

Comprehensive Asset Tracking
  • Catalog Attributes: Item Code, Name, Category, Quantity, Unit (pcs, box, kg), Unit Cost, Location, and Status.
  • Physical Condition: Categorized as New, Good, Fair, or Poor.
  • Permanent QR Code Generator: Generates unique vector QR tags for asset labeling (simplesoftwareio/simple-qrcode).
Thresholds & Low-Stock Prevention
  • Configurable Thresholds: Set minimum stock warnings per item.
  • Dedicated Low-Stock Screen: Filter and review all items requiring urgent reordering (/admin/inventories/low-stock).
  • Automated Administrator Alerts: Trigger notifications when stock drops below minimum operating limits.

4.4 Equipment Borrow Request Governance

  • Requisition Approval Queue: Inspect requesting employee, requested tool quantities, job justification, and due date.
  • Automated Stock Adjustments: Approving releases items and deducts stock; rejecting releases reserved stock back to active inventory.
  • Overdue Equipment Tracking: Automatic identification and flagging of borrow requests exceeding their expected return date.
  • Condition Degradation Auditing: Review condition discrepancies reported upon return (e.g., item borrowed as Good, returned as Poor with damage notes).

5.2 Automated Disaster Recovery & Backups

Powered by spatie/laravel-backup and managed through /admin/backups:

Scheduled Automation

• Daily Full Backup: Database + Application files at 2:00 AM.
• Weekly DB Snapshot: Sundays at 3:00 AM.
• Automated Cleanup: Daily at 3:30 AM enforcing retention rules.

SHA-256 Integrity

Every backup ZIP file is hashed with SHA-256. Administrators can trigger a one-click cryptographic verification to guarantee archives are corruption-free and uncompromised.

Cloud Storage & Alerts

• Direct ZIP download from admin panel.
• Optional Amazon S3 cloud replication.
• Automated email alerts to administrator upon backup completion or failure.

Strict Retention Policy: Retains all backups for 1 day, daily backups for 7 days, weekly snapshots for 4 weeks, monthly archives for 12 months, and yearly milestones for 2 years, enforcing an automatic 5,000 MB storage cap.

5.3 Tamper-Evident Cryptographic Audit Trail

The system logs all administrative, technician, and model operations in a secure audit log (/admin/audit-logs):

  • HMAC-SHA256 Checksum Chain: Each audit log entry includes a cryptographic checksum computed over the event timestamp, user ID, event type, and preceding log checksum. Any manual tampering with database rows invalidates the verification chain.
  • Granular Event Tracking: Tracks authentication (login/logout/failed attempts), model modifications (created/updated/deleted), administrative impersonations, and data exports.
  • Compliance Export: Full audit logs can be exported to CSV or PDF for external compliance reviews.

5.4 Multi-Entity Trash & Soft-Delete Management

To prevent accidental permanent data loss, the system incorporates a centralized trash management engine (/admin/trash) covering 5 key entity types:

Entity Type Soft-Delete Protection Administrative Recovery Actions
Bookings Cancelled or deleted customer service bookings. One-click restoration to active listings or password-confirmed permanent purge.
Borrow Requests Completed or rejected equipment requisitions. Restore historical borrow requests or securely delete after audit retention.
Inventory Items Decommissioned tools or depleted parts. Restore items with full stock histories intact, or permanently delete.
Inventory Categories Removed equipment categories. Restores category relationships without corrupting associated item records.
User Accounts Removed employee or administrator profiles. Restores credentials and historical assignments safely.
